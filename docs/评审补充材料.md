## 一、创新性：用「问题定义」立题

**一句话痛点**：古诗词学习散落在教材、注释书与背诵工具里，读不懂 → 记不住 → 用不上，没有一个地方能把「读懂、记住、用上」串起来。

**本系统的定位（唯一闭环）**：

```
检索（34.4 万首语料 + 双图谱） → 注解（RAG 四维注解，出处可点）
      → 背诵闯关（语音/填空，落库正确率） → 风格创作（格律后校验）
      → 社区（分享/共读） → 研习周报（回流为下一周的学习依据）
```

闭环不是功能罗列，而是**数据在同一套库表里流转**：检索与注解写入 `history` / `annotation_logs`，背诵写入 `quiz_records`，创作写入 `creations`，周报再把它们聚合成个人学习画像，并用这张画像反向生成「本周诗笺」。

### 1.1 交互创新：研习周报（`/workbench/weekly`）

| 模块 | 数据来源（真实库表） | 说明 |
| --- | --- | --- |
| 本周研习诗篇 | `history` 去重 `target_id` | 不是「打开次数」，是读过几首不同的诗 |
| 四维注解完成率 | `annotation_logs.answer` 解析 `zici/diangu/qinggan/geli` | 四节齐全才算完成，缺记录显示「—」而不是 0% |
| 背诵正确率 | `history.detail` 中「答对 x/y」 | 来自真实闯关结果 |
| 意象偏好分布 | `poem_imagery` + 诗篇正文意象字 | 标注覆盖不足时退回正文统计，仍为真实数据 |
| 本周诗笺 | 上述数据 → GLM → 自研格律校验 | 校验结果直接展示，不通过就标「格律有出入」 |

实拍（375px 真机视口，完整页面见 `docs/screenshots/mobile/weekly.png`）：本周 7 首诗、注解完成率 **71%（5/7）**、创作 22 首、意象 Top 为「山 5 首 / 春 3 首 / 月 2 首」。

### 1.2 技术创新：自研格律后校验器（`lib/meter.ts`）

不是调 API，是本地算法：按**中华新韵**校验押韵与平仄（律绝查偶数句同韵部、末字平仄硬规则、二四六交替软规则，一三五不论、首句入韵宽容；词按词牌韵脚查押韵），读音数据由 `scripts/gen_xinyun_data.py` 用 pypinyin 构建期生成，覆盖 4.2 万字、138KB，运行时零依赖。

**20 首生成实测（5 种风格 × 4 段现代文，2026-11-07，生产构建 + 真实 GLM 调用）**：

| 指标 | 实测 |
| --- | --- |
| 初检（首轮）整体格律通过 | **3 / 20（15%）** |
| 4 轮内自动重写后整体通过 | **10 / 20（50%）** |
| 押韵维度通过（重写后） | 12 / 20（60%） |
| 平仄维度通过（重写后） | 16 / 20（80%） |
| 平均尝试轮次 | 3.25 轮（1 轮 3 首 / 2 轮 1 首 / 3 轮 4 首 / 4 轮 12 首） |
| 分风格最终通过 | 王维 3/4、李白 2/4、苏轼 2/4、婉约 2/4、杜甫 1/4 |

结论口径：校验器的价值在于**能自动发现不合格并驱动重写**（合格率 15% → 50%，3.3 倍），而不是保证 100%；剩余 10 首在 UI 如实标注「格律有出入」，不伪装成合格。失败集中在七言律绝的韵部与平仄，属于免费档模型的能力边界。

## 三、实用性：两个明确 persona 与有效性数据

> 以下为产品设计 persona（典型用户画像），截图为真实产品页面，非虚构用户证言。

### 3.1 persona A：中学语文老师 · 备课找意象

- 场景：备《山居秋暝》，需要「意象 + 典故 + 情感 + 格律」四块材料，还要能给学生讲出处。
- 真实路径：`探索`（按朝代/标签筛）→ 诗篇详情 → `AI 智能注解` → 四维卡片（每张标注引用出处与相似度）→ `导出 Markdown` 进教案。
- 截图：[workbench_explore.png](../screenshots/desktop/workbench_explore.png)、[workbench_annotate.png](../screenshots/desktop/workbench_annotate.png)
- 收益：一次生成即得到可直接进课件的结构化材料，引用可点开核对。

### 3.2 persona B：诗词爱好者 · 创作练笔

- 场景：把周末爬山的现代文改成一首词，希望「像苏轼」，并且别写出不合律的句子。
- 真实路径：`风格迁移` → 选「苏轼体 · 定风波」→ 输入现代文 → 流式生成 → 格律徽章（✓/⚠）→ 生成水墨意境图 → 一键分享。
- 截图：[workbench_transfer.png](../screenshots/desktop/workbench_transfer.png)、研习周报 [weekly.png](../screenshots/mobile/weekly.png)（创作后回流到周报）
- 收益：从「不敢写」到「写完有人替你把格律关」。

### 3.4 角色分离：第三个视角与越权可验证性

除上述两个学习者 persona 外，系统另设**平台运营者**角色，对应「内容审核 / 用户治理 / 数据总览」这类真实运营场景。这一层不是页面装饰，权限边界可当场验证：

| 验证动作 | 期望结果 | 对应评分点 |
| --- | --- | --- |
| 用 `test@poetry.ai` 登录，观察侧边栏 | 不出现「管理后台」入口（`components/workbench/shell.tsx` 按 `user.role === 'admin'` 条件渲染） | 前端工程质量·组件化 |
| 普通账号直接访问 `/admin/users` | 服务端 `app/admin/layout.tsx` 重定向回 `/workbench` | 前端工程质量·代码质量 |
| 普通账号直接请求 `/api/admin/stats` | `lib/admin.ts` 的 `requireAdmin()` 返回 **403**，页面守卫不可绕过 | AI 技术深度·安全可控 |
| 切换 `admin@poetry.ai`（口令 `admin123`） | 六个后台页面与全部管理接口可用：用户禁用与详情、诗词增删改、分类运行时维护、帖子审核删除、反馈回复/重开、全站统计 | 实用性·场景真实性 |
| 管理员禁用某账号后，该账号旧会话 | `auth.ts` 的 `jwt` 回调实时查库，`role` 降级为 `disabled`，旧会话立即失效 | AI 技术深度·安全可控 |
| 普通账号发一帖后不刷新页面，管理员在 `/admin/posts` 点「通过」 | 用户端最多 5 秒自动变为「已通过审核 · 社区可见」并弹出提示；管理员待审队列与总览数字同步刷新（两端 `no-store` 轮询） | 用户体验·前端交互 / 前端工程质量 |
| 作者点「撤回帖子」后，管理员再尝试「通过」 | `PUT /api/admin/posts` 返回 **409 已被作者撤回，不可再次审批**；`PUT /api/posts/[id]` 先校验 `user_id`，无法代他人撤回 | AI 技术深度·安全可控 / 实用性·场景真实性 |
| 管理员在 `/admin/categories` 新增或改名一个分类，普通账号停留在发帖框不刷新 | 最多 5 秒后发帖选项与筛选按钮自动变化；改名会同步迁移该分类下的历史帖子，有帖子的分类删除被拒绝并提示数量 | 实用性·场景真实性 / 前端工程质量·代码质量 |
| 管理员回复一条反馈，普通账号停留在「帮助与反馈」 | 最多 10 秒后状态变为「已回复」并显示回复正文；管理端可修改回复、重新打开或删除 | 用户体验·前端交互 |
| 普通账号直接请求 `/api/admin/post-categories` 或 `/api/admin/users/[id]` | 新增的两个管理接口同样由 `requireAdmin()` 返回 **403**，权限边界没有因扩展功能出现缺口 | AI 技术深度·安全可控 |

会话 `role` 不写死在注册信息里，而是每次 `jwt` 回调查库；改密后 `passwordChangedAt` 校验使旧 JWT 失效。这两点配合「页面级 + 接口级 + 会话级」三层校验，是安全可控（4%）与前端工程质量（10%）两个维度里可直接演示、不依赖口头说明的硬证据。

> 演示路径建议：普通账号走完「AI 注解 → 引用高亮 → 风格迁移」主线；随后用同一账号发一帖，观察「管理员审批中 · 仅自己可见」，切换管理员账号在 `/admin/posts` 通过，再切回普通账号（或原地等待 5 秒）看到自动变为「已通过审核」并收到提示；最后可点「撤回帖子」验证撤回优先。这条跨账号闭环约 30–40 秒，同时覆盖角色分离、实时同步与数据权限三个点。两个评审账号均预置在 `data/ai_poetry.sql`，无需现场创建。

## 六、口径与局限（自查，避免被打假）

1. **演示账号数据不是真实用户数据**：周报页的「7 首 / 71% / 22 首创作」来自评审测试账号，其行为记录由本次 30 次采样调用产生；页面数据由库表现场计算，但样本主体是测试流量，PPT 应写「演示账号」，不写「真实用户」。
2. **格律 50% 只是一轮 20 首的实测值**：5 风格 × 4 文本、单次运行、最多 4 轮重写，不能外推为通用合格率；引用时须带「该轮 20 首」。
3. **采样时精排服务降级**：本次采样期间 rerank 接口返回分数数量不匹配，系统自动退回混合检索；token 与延迟数字真实，但不代表 CrossEncoder 精排全开的最优链路，修复后应重测再更新数字。
4. **引用类指标的口径是「引用条数」**：2/130、115/130 的分母均为被引诗题条数；越界引用 2/16→0/16 仅 16 条，只说明引用边界，不能外推整体幻觉率。
5. **未实测项**：教材逐篇覆盖、真实限流额度、并发压测、CI 远端绿灯均未验证；文档中一律不写。
