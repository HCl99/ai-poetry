# 技术实现对照说明（演示版交付）

> 本文档用于对齐《产品需求设计文档 v1.5》《UI 界面原型图设计文档 v2.5》与实际交付代码的实现差异。
> 答辩口径：PRD/UI 文档定义产品目标与验收标准；本文档说明工程实现的最终技术选型与实际 API/路由清单。
> 遵循"名实相符"原则：凡本文档未声称的能力，均属 V2 正式版规划。

## 一、技术栈对照（PRD 1.6 规划 → 实际实现）

| 层级 | PRD 规划 | 实际实现 | 选型理由 |
|---|---|---|---|
| 前端 | HTML5 + CSS3 + JS | **Next.js 14（App Router）+ TypeScript + Tailwind CSS** | 赛道推荐栈；SSR/流式原生支持；TS 全量零错误 |
| 后端框架 | FastAPI (Python) | **Next.js API Routes（Node.js）** | 前后端一体化部署，少一次跨服务网络开销，演示稳定性更高 |
| 数据库 | PostgreSQL | **MySQL + Prisma ORM** | ORM 参数化查询防注入；事务与索引能力满足业务 |
| 向量库 | ChromaDB | **自建向量检索层（lib/vectorStore.ts + embedding.ts）** | 混合检索：向量召回 + 关键词召回 + CrossEncoder 精排 + 无向量降级链路 |
| 大语言模型 | GPT-4o / Claude-3 / 通义千问 | **智谱 GLM-4-Flash（免费档）+ GLM-Z1（推理）** | 国产合规、免费额度覆盖演示全流程、OpenAI 兼容协议可随时切换 |
| RAG 框架 | LangChain + ChromaDB | **自研 RAG 管线**（混合检索→精排→引用硬约束→citationCheck 校验） | 引用硬约束+闭环评测（幻觉率 0%、归因率 93.8%），超出 LangChain 开箱能力 |
| Agent 框架 | LangGraph | **Function Calling 工具循环（lib/agentTools.ts）** | 模型自主规划调用 4 类图谱工具，工具轮完整 tool_calls 协议 |
| 多模态 | DALL·E 3 / SD | **文生图 + 图像理解（GLM-4V）+ 语音合成/识别** | 智谱 CogView-3-Flash 水墨意境图 + GLM-4V-Flash「以图搜诗」意象反查 + Web Speech 语音朗读 / 念诗输入 |
| 语音 | Web Speech / Azure TTS | **Web Speech API（识别+合成）** | 零成本零依赖；语音念诗输入 + 原诗朗读 |
| 向量嵌入 | text-embedding-3-large | **智谱 embedding-3（本地缓存）** | 与 LLM 同供应商，密钥与计费统一 |
| 认证 | JWT (OAuth2) | **NextAuth v4（JWT 会话）+ bcryptjs** | 注册 bcrypt 哈希、登录限流防爆破、记住我真实实现 |
| MCP | 协议工具封装 | **真实 MCP Server（JSON-RPC 2.0 over HTTP，POST /api/mcp）+ 可视化握手面板** | initialize / tools/list / tools/call 全链路可用；支持 `MCP_API_KEY` 供 Claude Desktop 等外部 Agent 直连 |
| 部署 | Vercel + Railway | **单服务 Next.js 生产构建** | 一体化部署，tsc 零错误 + build 全绿 |

## 三、API 实际路径清单（对 PRD 9.x 的对齐）

| PRD 规划路径 | 实际路径（Next.js API Routes） |
|---|---|
| POST /api/auth/login·register·logout | NextAuth 标准端点 + POST `/api/auth/logout` |
| GET /api/poetry?dynasty=… | GET `/api/poems/list`（朝代/作者/关键词/意象/分页） |
| GET /api/poetry/{id} | 诗篇详情由服务端组件直查 Prisma（含译文/赏析） |
| POST·DELETE /api/poetry/{id}/favorite | GET·POST·DELETE `/api/user/favorites` |
| POST /api/annotation/all（流式） | POST `/api/annotation`（SSE 流式，四维+引用） |
| POST /api/transfer/generate（流式） | POST `/api/transfer`（SSE 流式，5 风格） |
| 文生图 | POST `/api/inkpaint`（CogView 水墨意境图） |
| 图像理解（以图搜诗） | POST `/api/vision`（GLM-4V 识图 → 意象反查诗篇，结果页呈现「识图 → 反查 → 排序依据」三段可解释推理链） |
| GraphRAG 问答（Agent 工具循环） | POST `/api/graph-qa`（Function Calling + 引用校验） |
| POST /api/assistant/chat（流式） | POST `/api/assistant`（SSE 流式，多轮+RAG 引用） |
| 常规自测 + 飞花令 | POST `/api/feihua`（对战+RAG 校验）、quiz 由服务端出题 |
| 学习社区 | GET·POST `/api/community`（帖子/评论/点赞） |
| 个人中心 | `/api/user/favorites` `/notes` `/creations` `/summary` `/history` |
| GET /api/admin/* | `/api/admin/stats` `/users` `/poems` `/posts` `/feedback`（管理员守卫） |
| MCP | GET·POST `/api/mcp`（manifest + 本地模拟调用） |

统一响应：Next.js 生态惯例（HTTP 状态码 + JSON `{ error }`），MCP 端点遵循 PRD 9.1 的 `code/message/data/request_id` 格式。

## 五、质量与安全基线（答辩速查）

- 生产构建：`tsc --noEmit` 零错误、`next build` 全绿、vitest 29 例单测全过
- 引用硬约束：AI 输出仅允许引用检索列表内诗篇，`citationCheck` 逐条校验，闭环实验幻觉率 0%、归因率 93.8%
- 接口治理：AI 接口按成本分档限流（10~2 次/分钟）、登录/注册/MCP 限流防刷、全局错误边界、SSE 中断可停
- AI 安全：输入/输出双向内容过滤 + 违规兜底（`lib/content-filter.ts`）——输入侧拦截 prompt injection / 越狱、色情低俗、血腥暴力、仇恨歧视、违法交易并返回 400；注解 / 风格迁移 / AI 助手输出侧按最近 2000 字滚动校验，命中即中断 SSE 并回传安全提示；按明确违规语境匹配，正常古诗词字词不误杀
- 格律后校验（`lib/meter.ts`，自研算法）：风格迁移生成后按**中华新韵**校验押韵与平仄（律绝查偶数句同韵部 + 末字平仄硬规则 + 二四六交替软规则，一三五不论、首句入韵宽容；词按词牌韵脚查押韵），违规详情注入重写 prompt（计入 4 次上限），前端展示 ✓/⚠ 格律徽章；读音数据由 `scripts/gen_xinyun_data.py`（pypinyin）构建期生成，覆盖 4.2 万字、138KB，运行时零依赖
- 无障碍：`prefers-reduced-motion` 全动画降级、打字机 aria-label、键盘可达
